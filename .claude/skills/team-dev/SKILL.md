# team-dev — 에이전트팀 기반 개발 워크플로

설계·다파일 구현·리뷰가 포함된 작업(`$ARGUMENTS`)을 플랜 → 팀 구성 → 병렬 구현 → 검증 루프 → 종합 보고 순으로 수행한다.

**전제**: 에이전트팀은 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`일 때만 사용 가능하다. 이 환경변수가 없으면 아래 "팀원" 역할을 서브에이전트(`Agent` 도구)로 동일하게 구성해 진행한다. 워크플로 단계는 동일하다.

## 1. 플랜 (리더 직접 수행)
모델: Fable5 사용, 불가 시 Opus(별칭 `best`).

1. **요구 분석**: `$ARGUMENTS`를 분석해 목표와 범위, 제약을 정리한다.
2. **산출물 목록**: 생성·수정할 파일 목록과 각 파일의 소유자(팀원)를 정한다. 파일 세트는 팀원 간 겹치지 않게 분리한다.
3. **검증 완료 조건 작성** (필수):
   - 각 조건은 **명령 실행 결과로 기계적으로 판정 가능**해야 한다. 예: "`npx vitest run` 종료 코드 0", "`npm run typecheck` 에러 0건", "`npm run build` 종료 코드 0".
   - "동작이 자연스러움" 같은 주관적 조건은 금지한다.
   - **최대 루프 반복 횟수를 명시한다**(기본 5회).
   - 체크리스트 형태로 작성한다.
4. **사용자에게 플랜 제시**: 산출물 목록, 완료 조건 체크리스트, 최대 반복 횟수를 사용자에게 보여준다.

## 2. 팀 구성
- 작업 규모에 따라 **3–5명**을 구성한다.
- 역할별로 `.claude/agents/`의 정의를 활용한다: `planner`(설계·완료 조건), `implementer`(구현), `reviewer`(검증).
- **파일 소유권 분리**: 팀원마다 서로 다른 파일 세트를 소유하게 해 편집 충돌을 막는다.
- **스폰 프롬프트에 컨텍스트 필수 포함**: 팀원은 리더 대화 히스토리를 상속하지 않는다. 플랜, 완료 조건 체크리스트, 소유 파일, 관련 배경을 스폰 프롬프트에 반드시 넣는다.

## 3. 구현
- implementer 팀원들이 각자 소유한 파일을 **병렬로** 구현한다.
- 각 implementer는 자신의 완료 조건을 기준으로 자가 확인한 뒤 리더에게 보고한다.

## 4. 검증 루프
- reviewer가 **완료 조건 체크리스트 전체를 명령 실행으로 판정**한다. 항목별 충족/미충족과 근거(명령 출력)를 남긴다.
- 미충족 항목은 해당 implementer에게 전달해 수정하게 한 뒤 재검증한다.
- **성공 조건**: 완료 조건 전부 충족 → 루프 종료, 5단계로 진행.
- **중단 조건**: 최대 반복 횟수 도달, 또는 동일 실패 2회 연속 발생.
- 중단 시 리더가 미충족 항목·시도 내용·원인 분석을 사용자에게 보고한다.

## 5. 종합 보고
리더가 다음을 종합해 사용자에게 보고한다.
- **변경 파일**: 생성·수정된 파일 목록.
- **검증 결과**: 완료 조건 체크리스트의 항목별 충족 여부와 최종 명령 출력.
- **남은 리스크**: 미해결 항목, 후속 조치 필요 사항.

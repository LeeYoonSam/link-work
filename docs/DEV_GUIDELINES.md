# 개발 지침

이 문서는 CLAUDE.md가 import해 매 세션 로드된다. 확정 규칙만 두고, 사용법은 [DEV_WORKFLOW.md](DEV_WORKFLOW.md)에 있다. 예외 없는 규칙은 훅·설정으로 강제한다(문서 동기화는 Stop 훅, 테스트 수집 범위는 `vitest.config.ts`).

## 작업 경로
- 기본은 메인 세션 단독 구현이고, 코드를 쓰는 쪽은 하나다 — main·preload·renderer·IPC 계약이 얽혀 있어 병렬로 쓰면 가정이 어긋난다.
- IPC 채널, DB 스키마, 프로세스 경계를 넘는 다파일 변경은 구현을 마친 뒤 `reviewer` 서브에이전트(`.claude/agents/reviewer.md`)를 한 번 부른다 — 작성자와 분리된 리뷰가 실제 결함을 잡았다.
- 설계 판단이 없는 작은 변경은 리뷰 없이 끝내도 된다. 원하면 `/code-review`를 쓴다 — 리뷰 비용을 변경 위험에 맞춘다.
- 독립 묶음이 2개 이상이거나 리서치·시안 경쟁·찬반 토론·전수 점검이 필요하면 Claude Code 내장 Workflow 도구를 쓴다. 사용자가 "워크플로로"라고 요청할 때 실행하고, 필요해 보이면 먼저 제안한다 — 중간 결과가 메인 컨텍스트에 쌓이지 않지만 토큰이 많이 든다. 저장소 밖 개인 스킬에 기대지 않는다.
- Agent Teams는 사용자가 요청할 때만 그 세션에서 환경변수로 켠다 — 상시로 켜 두면 일반 서브에이전트까지 팀원으로 바뀐다.

## 완료 조건과 검증
- 구현 전에 완료 조건을 CLAUDE.md 검증 명령으로 정한다. 코드를 바꾸면 `npm run check:docs` 종료 코드 0을 넣는다 — 기계 판정만 믿을 수 있다.
- 범위가 크거나 요구가 불확실하면 플랜 모드로 계획하거나, 질문으로 요구를 확정한 뒤 짧은 스펙을 쓴다 — 구현 뒤 되돌리는 비용이 더 크다.
- 구현 중에는 필요한 테스트를 자유롭게 돌린다. 최종 판정 실행은 모든 편집이 끝난 뒤 한 번만 한다. reviewer를 부르는 작업이면 메인 세션은 돌리지 않고 reviewer가 맡는다. 같은 작업 트리에서 빌드를 동시에 돌리지 않는다 — 중복 실행과 out/ 충돌을 막고 레드-그린 반복은 살린다.
- `npm run deploy`, `npm run check:diar`, `npm run check:diar-mem`은 메인 세션이 맡는다 — /Applications 쓰기, 키체인 입력, 장시간 실녹음 실행이 따른다.
- 실패 0건은 기존 실패에도 적용한다. '무관'으로 통과 처리하지 않고, 고치지 못하면 완료로 보고하지 않고 사용자에게 알린다 — 말로 정한 기준은 쉽게 무너진다.
- 수정→검증 반복은 3회까지 한다. 같은 실패가 2회 연속이면 접근을 바꾸거나, 멈추고 미충족 항목·시도·원인을 보고한다 — 그 이상 반복해도 나아지지 않았다.
- 버그 수정은 재현 테스트를 먼저 쓴다. 테스트를 지우거나 약하게 바꿔 통과시키지 않는다 — 테스트가 버그를 잡는지 먼저 확인해야 수정이 증명된다.

## 위임
- 서브에이전트 모델은 에이전트 정의의 `model`에 맡기고, 호출할 때 바꾸지 않는다 — 즉석에서 낮은 모델로 검증한 일이 있었다. 메인 세션 모델은 `/model`, 노력도는 `/effort`로 정한다.
- 서브에이전트 프롬프트에는 목표, 출력 형식, 파일 범위, 완료 조건, 이미 돌린 명령 결과를 담는다 — 대화 기록을 물려받지 않는다.
- 몇 번의 도구 호출로 끝낼 일은 위임하지 않는다 — 위임은 토큰 비용이 크다.
- reviewer의 지적은 심각도로 거르지 않고 전부 받은 뒤 메인 세션이 고칠 것을 고른다. 있을 수 없는 경우를 위한 방어 코드나 테스트는 더하지 않는다 — 찾으라고 하면 리뷰어는 늘 뭔가를 찾는다.

## 마무리
- 최종 보고에는 완료 조건별 명령·결과, 바꾼 파일, 문서 동기화 결과(고칠 것이 없으면 근거 한 줄), 커밋·푸시·deploy 수행 여부를 담는다. 하지 않은 단계가 있으면 다음 명령을 제안한다 — 마무리를 매번 따로 요청하지 않게 한다.
- 한 작업에 서로 무관한 변경(예: 제품 버그 수정과 개발 워크플로 개편)이 섞이면 커밋을 나눈다. 코드와 그 대응 문서는 같은 커밋에 둔다 — 되돌리기와 리뷰 범위를 나누되 문서 동기화는 깨지 않는다.

## 지침 작성
- 지침·스킬·에이전트 파일에는 강조 대신 이유를 쓴다. 계속 무시되는 규칙은 강조를 더하지 말고 훅이나 설정으로 옮긴다 — 최신 모델은 강조어에 과잉 반응하고, 말로 된 규칙은 강제되지 않는다.
- 확정 규칙은 이 문서에 두고 CLAUDE.md의 import 줄로 상시 로드한다 — docs/ 아래에 있어 `check:docs` 검사와 docs-map 추적을 받는다.
